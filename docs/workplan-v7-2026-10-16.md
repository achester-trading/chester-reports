## 1. The rhythm, as amended

v6's three slots stand (overnight sessions, morning rulings, evening merges). Amended:

- **One combined paste per session per night**, its parts in order, rather than two queued messages. A message typed into a running session can interleave with its work.
- **Decisions are listed, not waited on.** Where a paste gives a default, the session takes it and records it. Otherwise it stops that item, lists it under Needs you and moves to the next part.
- **The memory rule** (from 14–15 Oct):
  - Run locally only the gates the session writes or changes, or whose files a merge conflict touched, one at a time.
  - Leave every other gate, and anything that renders a PDF, to CI.
  - Leave no background command waiting on CI.
  - On a low-memory warning, push and read CI. Never wait for the operator.
- **One chain at a time.** New work branches from the tip of the current stitched chain, or from main once that chain has merged. Before each merge evening, one session stitches every branch since the last merge into one cumulative chain in merge order, as on 13–14 and 15 Oct. Each merge is then clean.
- **Merge evenings: Monday and Thursday.** Friday 16 Oct is the first. Each one merges one chain, docs-only branches last.
- **The laptop.** Keep it plugged in with sleep off. In the morning, type "continue" into any session that stopped on a connection drop (14 and 16 Oct).

## 7. Risks the faster cadence adds, and the rule for each

- **Merge debt.** One stitched chain per merge evening. Nothing branches from anything but the chain's tip.
- **Review volume.** Claude reads every notes file and brings the rulings, not the reports. A needs-you list holds at most five items, each with a default.
- **The laptop.** It handles two sessions, never three, under the memory rule. Keep sleep off; "continue" after a drop.
- **Usage limits.** Heavy overnight queues can reach the plan's limit, as the FlashAlpha pull did at 16:25 on 14 Oct. A stopped session resumes with "continue". A failed scheduled task is recorded and not retried blindly.
- **The Brookfield restriction across systems.** chester-reports enforces it in Python and SQLite, and chester-meme now carries its own. Whether the contract schema should carry `restricted` is open.
- **The box.** Overnight work never touches it. Monday's box evening is long and may spread into Tuesday. Nothing runs on the box outside the windows.

## 8. Rules carried forward (from v6, unchanged)

Paper trading only; sessions never place orders. No Brookfield-complex trades (blocklist in Python and SQLite). One task, one machine; every paste names its session and carries a time estimate. Sessions may validate, deploy and use git; they print unit commands, never run them. `decide.py record`, narrative confirm or reject, `.env`, register writes and `systemctl --user enable` are the operator's. A push to main is a box write and happens only inside the windows. CI is the validate. No secrets and no real position figures in any chat, commit or file. Code gates never read the live store. Reports never fetch. Pastes are plain ASCII, and an amended paste is recreated in full.
